#  Shared File Systems

== RHOSP Storage Options

Red Hat OpenStack Platform (RHOSP) offers various storage options to meet diverse data storage needs. Among these, Shared File Systems play a crucial role in providing persistent, shared storage for virtual machines and bare metal instances.

### Shared File Systems Overview

Shared File Systems in RHOSP are built on top of the open-source project, Manila, which provides a highly scalable distributed file system service for multitenancy cloud environments. Manila allows users to create and manage file shares in a self-service manner, providing a simple and intuitive interface to provision complex storage solutions.

### Key Features of Shared File Systems

1. **Multitenancy**: Manila supports multiple tenants, enabling secure isolation of storage resources.
2. **Share Types**: Users can define share types with specific performance levels and features, such as QoS, snapshot support, and replication.
3. **Share Protocols**: Manila supports various share protocols, including NFS, CIFS, and GlusterFS, allowing compatibility with a wide range of clients.
4. **Snapshots and Cloning**: Users can create snapshots and clone shares for backup and testing purposes.
5. **Scalability**: Manila is designed to scale horizontally, allowing for seamless expansion of storage capacity and performance.

### Shared File System Components

1. **Manila API**: The core component responsible for managing storage resources and handling requests from clients.
2. **Manila Scheduler**: Determines the appropriate backend driver to handle share creation and management.
3. **Backend Drivers**: Implement the actual storage functionality, such as CephFS, NFS, and GlusterFS.
4. **Manila Share Service**: Manages the lifecycle of shares, including creation, deletion, and snapshot management.
